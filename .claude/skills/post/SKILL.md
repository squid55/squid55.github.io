# /post — 글 올리기

사용자가 준 내용(대화에서 쓴 글, 붙여넣은 마크다운, 메모 파일, 사진 폴더, PDF)을
블로그 글 하나로 만들어 배포까지 한다. `CLAUDE.md` 의 문체·사진 규칙을 그대로 따른다.

## 1. 재료 확인

- 사용자가 준 것이 무엇인지 먼저 정리한다: 본문이 될 글 / 사진 / PDF / 참고 자료.
- 파일 경로를 받았으면 **읽고 나서** 쓴다. 사진은 눈으로 확인한다(방향, 내용, 개인정보).
- 본문이 될 내용이 부족하면 지어내지 말고 사용자에게 묻는다.

## 2. 분류와 슬러그

| 내용 | 경로 |
|---|---|
| V4L2 · 미디어 | `content/kernel/v4l2/<슬러그>.md` |
| eBPF | `content/kernel/ebpf/<슬러그>.md` |
| 스케줄러 · 메모리 · 인터럽트 등 커널 내부 | `content/kernel/internals/<슬러그>.md` |
| 임베디드 펌웨어 · C/C++ 구조 | `content/embedded/<슬러그>.md` |
| 컨퍼런스 · 모임 후기 (사진 있음) | `content/conference/<YYYY-MM-DD-슬러그>/index.md` |
| PDF 가이드 | `content/guides/<슬러그>/index.md` |

- 슬러그는 영문 소문자와 하이픈. 한글을 쓰지 않는다.
- 새 분류가 필요하면 폴더와 `_index.md`(제목만) 를 만든다. 설명문은 넣지 않는다.
- `hugo new content <경로>` 로 만들면 틀이 잡힌다.

## 3. 본문 작성

- `CLAUDE.md` 의 **문체** 절을 따른다. 사용자가 쓴 표현을 최대한 살리고, 문장만 다듬는다.
- 사용자의 메모에 있는 판단·감상은 그대로 두고, 없는 것을 만들지 않는다.
- 자료(녹취·PDF·슬라이드)에서 사실을 보충할 때는 자료에 있는 것만 쓴다.
- 인물은 소속과 역할까지 확인해서 적는다. 확인 못 한 것은 적지 않고 사용자에게 묻는다.
- `date` 는 **글을 쓴 날**. 행사 날짜는 본문에 쓴다.

## 4. 사진과 PDF

```bash
python3 tools/prep_photos.py <원본...> -o content/<...>/img    # 2500px, EXIF 제거
```

- 방향이 틀어진 사진은 눈으로 확인하고 바로 세운다.
- 글에서 그 이야기를 하는 자리에 이미지를 넣고, 설명(alt)과 캡션을 단다.
- 사진이 없는 발표는 PDF 에서 해당 쪽을 `pdftoppm -r 150 -f <쪽> -l <쪽> -png` 로 뽑아 쓴다.
- 슬라이드·자료 캡처에는 캡션에 발표자와 출처를 적는다.
- `cover` 로 쓸 대표 이미지를 하나 정한다.

## 5. 검사

```bash
hugo --gc --minify --panicOnWarning
```

깨진 링크, 없는 사진, 잘못된 숏코드가 있으면 여기서 실패한다. 통과할 때까지 고친다.
로컬 서버(`hugo server -D --enableGitInfo=false`)가 떠 있으면 실제 화면도 확인한다.

## 6. 사용자 확인

커밋 전에 한 번 멈추고 보고한다.

- 어떤 글을 어느 경로에 만들었는지
- 이미지 몇 장을 어떻게 처리했는지
- 미리보기 주소(`http://localhost:1313/...`)
- 확인이 필요한 것(사람 이름·소속, 애매한 사실, 개인정보)

사용자가 "올려"라고 하면 다음으로 간다. 자료의 공개 여부는 다시 묻지 않는다.

## 7. 커밋과 푸시

```bash
git add <만든 파일들>
git commit -m "<글 제목>"      # 본문 아래에 Co-Authored-By 줄을 붙인다
git push
```

푸시 후 배포를 확인한다.

```bash
gh run watch $(gh run list --workflow=pages.yml --limit 1 --json databaseId --jq '.[0].databaseId') --exit-status
curl -s -o /dev/null -w '%{http_code}\n' https://squid55.github.io/<글 주소>/
```

200 이 나오면 사용자에게 실제 주소를 알려준다. 1~2분 걸린다.

## 주의

- 저장소는 공개다. 커밋하는 순간 인터넷에 공개된다.
- `draft: true` 가 남아 있으면 배포되지 않는다. 올릴 글에서는 지운다.
- 사용자가 요청하지 않은 글이나 문구를 만들지 않는다.
